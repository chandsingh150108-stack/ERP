# NoteHub — Exhaustive Feature Specification

> **Status:** Design locked, ready for build.
> **Source:** Consolidates `a feature called notehub, students can u.md` + all clarifications from planning session.
> **Goal:** When an agent reads this file in the future, it can instantly implement NoteHub without asking questions.

---

## 1. Original Requirement (verbatim)

> a feature called notehub, students can upload their notes and every student can access it. just like how in the vault, we can upload notes either connected to a course or custom, students should be able to submit notes. after clicking the notehub button, it should prompt the student to choose between Course note and extra notes. and both should open different web pages. in the the course note page. there should be an add new button and after clicking add new there should be options like, YEAR_-> COURSE -> SUBJECT-> UNIT(I -> VI). and to search/sort the notes there should be an option exactly like shown before YEAR_-> COURSE -> SUBJECT-> UNIT(I -> VI). and after choosing the unit, only the top 5 options should appear and the ranking is decided by a simple upvote option. Other uploaded notes can be loaded by using the load more option but shouldn't show automatically only the Top 5 option. In the custom note webpage, the notes should be accessed by text based searching for e.g.searching for AI, should show -> How AI works?, what is ai? etc.

## 2. Locked Decisions (session Q&A)

| # | Question | Answer (LOCKED) |
|---|----------|-----------------|
| 1 | Upload format | **PDF notes only.** Validate `contentType == application/pdf` AND filename ends `.pdf`. Reject everything else with 400. Max 50MB (reuse existing multipart limits). |
| 2 | Taxonomy YEAR → COURSE → SUBJECT → UNIT | **YEAR** = study year `Integer 1-4` (NOT `AcademicYear.yearName`). **COURSE** = existing `Course` entity, selected via `Course.code` (e.g. `AI1302`, `CS101`). **SUBJECT** = **new entity `NoteHubSubject`** (admin-created, see §4). **UNIT** = enum/string `I, II, III, IV, V, VI`. Example: `YEAR 2 → AI1302 → Data Structures and Algorithms → Unit III`. |
| 3 | Upvotes | **Toggle on/off, one per student per note.** `POST /{id}/upvote` creates vote + `voteCount++` if absent; deletes vote + `voteCount--` if present. Enforced by DB unique constraint `(note_id, student_id)`. No self-vote restriction (students may upvote own notes unless later changed). |
| 4 | Permissions | **Upload: `STUDENT` only** (`@PreAuthorize("hasRole('STUDENT')")`). **View/download/search: any authenticated user** (`ADMIN`, `FACULTY`, `STUDENT`). **Delete: owner-student OR `ADMIN`/`FACULTY`.** Stranger `STUDENT` gets 403. **Subjects CRUD: `ADMIN` only** (autogenerated by admin like courses — students only select, never create). **Upvote: `STUDENT` only.** |
| 5 | Extra notes | Fields: `title + description + PDF file`. Search must match text in **both** `title` AND `description` (case-insensitive LIKE, same pattern as `StudentRepository.search`). No YEAR/COURSE/SUBJECT/UNIT for EXTRA. Same Top-5 + Load-more + upvote behavior recommended (or plain ranked list — default to same Top-5 for consistency). |
| 6 | Subject creation | **Subjects are autogenerated by admin like courses.** New `NoteHubSubjectController` with `GET` for all, `POST/PUT/DELETE` for `ADMIN` only. Students pick from dropdown in `Add New` modal. |

No open questions. Ready to build.

## 3. How NoteHub Differs From Vault (critical context)

| Aspect | Vault (`/api/vault/*`) | NoteHub (`/api/notehub/*`) |
|--------|------------------------|----------------------------|
| Visibility | **Private** — `resolveStudentId(auth)` scopes to logged-in student; student A cannot see B's items | **Global** — all students see all notes; no `studentId` scoping on reads |
| Upload | Any file type, `category` field, optional `subjectId` (personal `VaultSubject`) | PDF only, `noteType` (COURSE/EXTRA), taxonomy FKs |
| Ranking | None (list/filter) | `voteCount` DESC + Top-5 + Load-more |
| Subjects | Per-student `VaultSubject` (student creates own) | Global `NoteHubSubject` (admin creates, all students share) |
| Delete | Owner (scoped by `findByIdAndStudentId`) | Owner OR admin/faculty (global lookup by `id`) |
| Storage dir | `./uploads/vault/{studentId}/` | `./uploads/notehub/` (flat + UUID prefix; optionally `{noteId}/` subfolder) |

Do NOT copy Vault's `resolveStudentId` scoping for reads. Only use it on upload/upvote to identify the caller.

## 4. Domain Model

### 4.1 `NoteHubSubject` → table `notehub_subjects`
New global taxonomy node. Mirrors `Course` admin-managed pattern.

```java
@Entity @Table(name="notehub_subjects",
  uniqueConstraints=@UniqueConstraint(columnNames={"course_id","code"}))
@Data @Builder @NoArgsConstructor @AllArgsConstructor
public class NoteHubSubject {
  @Id @GeneratedValue(IDENTITY) Long id;
  @Column(nullable=false, length=20) String code;        // e.g. AI1302
  @Column(nullable=false, length=150) String name;       // e.g. Data Structures and Algorithms
  @Column(nullable=false) Integer studyYear;             // 1-4, validate @Min(1) @Max(4)
  @ManyToOne(fetch=LAZY) @JoinColumn(name="course_id", nullable=false) Course course;
  LocalDateTime createdAt; // @PrePersist
}
```

### 4.2 `NoteHubNote` → table `notehub_notes`

```java
@Entity @Table(name="notehub_notes")
@Data @Builder @NoArgsConstructor @AllArgsConstructor
public class NoteHubNote {
  @Id @GeneratedValue(IDENTITY) Long id;
  @Column(nullable=false, length=10) String noteType;    // COURSE | EXTRA
  @Column(nullable=false, length=200) String title;
  @Column(length=1000) String description;
  @Column(nullable=false, length=255) String fileName;   // original name
  @Column(nullable=false, length=500) String filePath;   // disk path
  @Column(nullable=false) Long fileSize;
  @Column(nullable=false, length=100) String fileType;   // application/pdf
  @ManyToOne(fetch=LAZY) @JoinColumn(name="uploader_id", nullable=false)
    @JsonIgnoreProperties({...}) Student uploader;
  // COURSE-only (nullable for EXTRA):
  Integer studyYear;                                     // 1-4
  @ManyToOne(fetch=LAZY) @JoinColumn(name="course_id") Course course;
  @ManyToOne(fetch=LAZY) @JoinColumn(name="subject_id") NoteHubSubject subject;
  @Column(length=10) String unit;                        // I..VI
  @Column(nullable=false) @Builder.Default Integer voteCount = 0;
  LocalDateTime createdAt; LocalDateTime updatedAt;      // @PrePersist/@PreUpdate
}
```

Validation rules:
- If `noteType==COURSE`: `studyYear, course, subject, unit` all required; `subject.course.id` must equal `course.id`; `subject.studyYear` must equal `studyYear` (prevent mismatched cascade).
- If `noteType==EXTRA`: taxonomy fields must be null.
- File: PDF-only check in service (not just frontend `accept=.pdf`).

### 4.3 `NoteHubVote` → table `notehub_votes`

```java
@Entity @Table(name="notehub_votes",
  uniqueConstraints=@UniqueConstraint(columnNames={"note_id","student_id"}))
@Data @Builder @NoArgsConstructor @AllArgsConstructor
public class NoteHubVote {
  @Id @GeneratedValue(IDENTITY) Long id;
  @ManyToOne(fetch=LAZY) @JoinColumn(name="note_id", nullable=false) NoteHubNote note;
  @ManyToOne(fetch=LAZY) @JoinColumn(name="student_id", nullable=false) Student student;
  LocalDateTime createdAt; // @PrePersist
}
```

  `existsByNoteIdAndStudentId(Long, Long)`, `deleteByNoteIdAndStudentId(Long, Long)`, `countByNoteId(Long)`

## 6. Services

### `NoteHubSubjectService`
- `create(dto)`: verify `Course` exists, check `existsByCourseIdAndCode`, validate `studyYear 1-4`, save.
- Standard `update/delete/find` (ADMIN-gated at controller).

### `NoteHubService` (mirrors `VaultItemService.create/delete/download`)
- `create(MultipartFile file, title, description, noteType, studyYear, courseId, subjectId, unit, uploaderStudentId)`:
  1. Verify uploader `Student` exists.
  2. PDF check: `application/pdf` + `.pdf` extension → else `IllegalArgumentException("Only PDF files allowed")`.
  3. If COURSE: validate all taxonomy + cross-consistency (subject belongs to course + year).
  4. `Files.createDirectories(Paths.get(notehub.upload-dir))`; stored name `UUID_original.pdf`; `file.transferTo(...)`.
  5. Save with `voteCount=0`.
- `delete(noteId, callerUsername, callerRoles)`: load by `id` (global, NOT scoped); allow if `note.uploader.username == caller` OR `ADMIN/FACULTY`; `Files.deleteIfExists` + `delete(note)`; cascade-delete votes.
- `download(noteId)`: global read, return bytes + contentType + fileName.
- List/search methods return `Page<NoteHubNote>` ordered `voteCount DESC, createdAt DESC`.

### `NoteHubVoteService.toggle(noteId, studentId)` `@Transactional`
- If `exists` → `deleteBy...`, `note.setVoteCount(max(0, c-1))`, return `{voted:false, voteCount}`.
- Else → save vote, `note.setVoteCount(c+1)`, return `{voted:true, voteCount}`.

## 7. REST API Contract

Base: `/api/notehub`. Auth: `Authorization: Bearer <token>`. Errors via existing `GlobalExceptionHandler` (400/401/403/404/500 schemas in AGENTS.md §10).

| Method | Endpoint | Access | Params / Body | Response | Notes |
|--------|----------|--------|---------------|----------|-------|
| GET | `/api/notehub/subjects` | Authenticated | `?year=2&courseId=3` (both optional, for cascade) | `List<NoteHubSubject>` | Populate COURSE→SUBJECT dropdown |
| POST | `/api/notehub/subjects` | `ROLE_ADMIN` | Body `{code, name, studyYear, course:{id}}` | `NoteHubSubject` | Admin creates subject |
| PUT | `/api/notehub/subjects/{id}` | `ROLE_ADMIN` | Body | `NoteHubSubject` | |
| DELETE | `/api/notehub/subjects/{id}` | `ROLE_ADMIN` | — | 200 | Block if notes reference it (or set null — decide: block with 400 to preserve taxonomy integrity) |
| GET | `/api/notehub/notes` | Authenticated | `?type=COURSE&year=2&courseId=1&subjectId=5&unit=III&limit=5&offset=0` | `List<NoteHubNote>` (+ `X-Total-Count` header or `{items,total}` wrapper) | **Default `limit=5`** — Top-5 only. `Load more` → `offset=5,10…`. Sort server-side `voteCount DESC`. |
| GET | `/api/notehub/notes/search` | Authenticated | `?type=EXTRA&keyword=AI&limit=5&offset=0` | `List<NoteHubNote>` | LIKE on title+description |
| GET | `/api/notehub/notes/{id}` | Authenticated | — | `NoteHubNote` | Global (no owner check) |
| GET | `/api/notehub/notes/{id}/download` | Authenticated | — | `application/pdf` bytes, `Content-Disposition: attachment` | Mirror `VaultItemController.downloadFile` |
| POST | `/api/notehub/notes` | `ROLE_STUDENT` | Multipart `file(PDF), title, description?, noteType, studyYear?, courseId?, subjectId?, unit?` | `NoteHubNote` | Uploader = caller via `resolveStudentId` |
| DELETE | `/api/notehub/notes/{id}` | `STUDENT`+`ADMIN`+`FACULTY` (+ service owner check) | — | 200 | Owner or admin/faculty only; delete disk file + votes |
| POST | `/api/notehub/notes/{id}/upvote` | `ROLE_STUDENT` | — | `{voted:boolean, voteCount:int}` | Toggle |

## 9. Frontend (static vanilla JS, mirrors `vault/index.html` — avoids rebuilding React bundle)

Location: `backend/src/main/resources/static/notehub/`

- `index.html` (picker): two cards `Course note | Extra notes` → navigate to `./course.html` / `./extra.html`. Include NoteHub button entry point from main navbar (React bundle change deferred — direct URL access works immediately).
- `course.html`:
  - Filter bar: `YEAR (1-4) → COURSE (GET /api/courses) → SUBJECT (GET /api/notehub/subjects?year=&courseId=) → UNIT (I-VI)` selects. Filtering SUBJECT dropdown on YEAR+COURSE selection.
  - `Add New` button → modal with same cascade + `title, description, PDF input (accept=.pdf)`.
  - Results: render Top-5 cards (title, `YEAR • CODE • Subject • Unit III`, `▲ Upvote (n)`, uploader roll, download btn). `Load more` button → `offset+=5` fetch and append. No auto-load beyond 5.

  - Search input (debounced ~300ms) → `GET /api/notehub/notes/search?type=EXTRA&keyword=`; empty keyword → list Top-5 EXTRA.
  - Upload form: `title, description, PDF` only.
  - Same upvote/download/list components.

## 10. Tests (`NoteHubTest.java`, `@SpringBootTest @Transactional @ActiveProfiles("test")`, mirrors `VaultTest`)

1. Admin creates subject; duplicate `(course,code)` fails.
2. Student uploads PDF COURSE note with valid cascade → 200; non-PDF → 400.
3. Mismatched subject/course/year → 400.
4. Student B lists/downloads student A's note (global visibility — inverse of Vault isolation test).
5. Upvote toggle: vote → count 1, `voted:true`; again → count 0, `voted:false`; duplicate-row impossible (unique constraint).
6. Top-5 ordering: seed 7 notes with varied votes → default fetch returns 5 sorted; `offset=5` returns remaining 2.
7. EXTRA search: `AI` matches `How AI works?` (title) and `what is ai?` (description, case-insensitive).
8. Delete: owner ok; stranger STUDENT 403; ADMIN/FACULTY ok + file removed from disk.
9. STUDENT cannot POST subjects (403); unauthenticated GET notes → 401/403.

## 12. Edge Cases & Pitfalls (from AGENTS.md §15 + new)

- Don't reuse Vault's owner-scoped read (`findByIdAndStudentId`) for NoteHub — global `findById`.
- `voteCount` denormalized: keep in `@Transactional` toggle to avoid drift; consider `@Modifying increment` query under concurrency.
- PDF spoofing: check magic bytes (`%PDF`) in addition to MIME/extension if hardening needed.
- Subject delete with existing notes: BLOCK (400) to keep cascade intact (preferred over nulling).
- `Backlog.semester→AcademicYear` quirk and `UserRoleId` orphan unaffected.
- Docker: if `docker compose up` fails with `Conflict. container name /student-erp-backend already in use`, run `docker rm -f student-erp-backend` first (seen in session).
